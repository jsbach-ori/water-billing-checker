## 1. 目的

不動産管理業務で、物件ごとの水道料金を水道局に電話で照会し、請求額を検算して記録する作業を効率化する。

### 現状の作業フロー（改善前）
1. 前回の「水道のお知らせ」PDFを探して印刷する
2. 照会に必要な情報（お客様番号など）を紙から探し、水道局へ電話する
3. 聞き取った期間・水量・金額を紙に赤字で記録する
4. 必要に応じて水道局の料金計算ページで料金を確認する
5. 従量料金などを電卓で計算し、記入する

### 改善後の作業フロー
物件を選択 → 表示された情報を見ながら電話 → 回答を入力 → 自動計算・差額判定 → PDF保存

### コンテストでの位置づけ
- AIカレッジ学園コンテスト「Claude Codeで開発したアプリ」部門に提出する
- 最重要の審査項目は**生産性向上効果（削減できる作業時間を数値で示す）**。そのため、作業時間を計測する機能を組み込む
- 提出物：アプリのタイトル、概要（100文字程度）、**公開URL**、画面キャプチャ（最大5枚）または動画
- 締切：**2026年11月15日（日）18:00**

## 4. 料金計算仕様（東京都23区・一般用）

出典：
- 東京都水道局「水道料金・下水道料金の計算方法（23区）」https://www.waterworks.metro.tokyo.lg.jp/tetsuduki/ryokin/keisan_23
- 東京都下水道局「下水道料率表」https://www.gesui.metro.tokyo.lg.jp/living/fee/keisan/ryokinhyo

### 4.1 水道 基本料金（1か月・税抜）
| 口径(mm) | 13 | 20 | 25 | 30 | 40 | 50 | 75 | 100 | 150 | 200 | 250 | 300以上 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 円 | 860 | 1,170 | 1,460 | 3,435 | 6,865 | 20,720 | 45,623 | 94,568 | 159,094 | 349,434 | 480,135 | 816,145 |

口径の値は数値で持つ。「300」は300mm以上を表す。

### 4.2 水道 従量料金（1か月・円/m³・税抜）
| 1か月の使用水量 | 13〜25mm | 30・40mm | 50・75mm | 100mm以上 |
|---|---|---|---|---|
| 1〜5m³ | 0 | 213 | 372 | 404 |
| 6〜10m³ | 22 | 213 | 372 | 404 |
| 11〜20m³ | 128 | 213 | 372 | 404 |
| 21〜30m³ | 163 | 213 | 372 | 404 |
| 31〜50m³ | 202 | 213 | 372 | 404 |
| 51〜100m³ | 213 | 213 | 372 | 404 |
| 101〜200m³ | 298 | 298 | 372 | 404 |
| 201〜1,000m³ | 372 | 372 | 372 | 404 |
| 1,001m³以上 | 404 | 404 | 404 | 404 |

段階ごとの累進で計算する。各段階の幅に収まる水量×その段階の単価を合計する。
30mm以上の単価は公式表の結合セルから読み取った値で、公式の早見表では検証できていない。画面の料金表に「大口径は公式表で要確認」と注記する。

### 4.3 下水道（一般汚水・1か月・税抜）
最低料金付きの従量逓増料金制。
| 1か月の排出量 | 料金 |
|---|---|
| 0〜8m³ | 560円（定額） |
| 9〜20m³ | 110円/m³ |
| 21〜30m³ | 140円/m³ |
| 31〜50m³ | 170円/m³ |
| 51〜100m³ | 200円/m³ |
| 101〜200m³ | 230円/m³ |
| 201〜500m³ | 270円/m³ |
| 501〜1,000m³ | 310円/m³ |
| 1,001m³以上 | 345円/m³ |

- 排出量は使用水量と同じとみなす
- 画面では「基本料金」＝8m³までの定額560円、「従量料金」＝9m³以上の部分として表示する

### 4.4 2か月分の計算（通常の請求）
1. 2か月の使用水量 Q を、1か月目 `ceil(Q/2)` と2か月目 `Q − ceil(Q/2)` に分ける（Qが奇数なら1か月目に1m³多く配分する）
2. 月ごとに水道（基本＋従量）と下水道（定額＋従量）を計算する
3. 2か月分を合算し、水道と下水道それぞれで消費税を計算する
   - `税込 = floor(税抜合計 × (100 + 税率) / 100)`
   - `消費税 = 税込 − 税抜合計`
4. 基本料金無償化フラグがオンで口径が25mm以下なら、水道の基本料金を0にする（期間限定措置の試算用。初期値はオフ）
   - 設定「基本料金無償化の入力欄を表示する」がオフ（初期値）のときは、無償化なしとして計算する（6.1.4）

検算：口径20mm・59m³なら水道9,038円、下水道7,062円、合計16,100円（公式の計算例と同じ）。

### 4.5 日割り計算（S1・対象外：コンテスト版では画面を作らない）
計算エンジンの `calcProrated` と、cases.json の日割り4件のテストは残す（今後の拡張用）。
- 水道：
  1. 換算水量 = `floor(使用水量 × その月の日数 ÷ 使用日数)`
  2. 1か月分 = 基本料金 + 換算水量で計算した従量料金
  3. 日割り後 = `floor(1か月分 × 使用日数 ÷ その月の日数)`
  4. 税込 = `floor(日割り後 × (100 + 税率) / 100)`
- 下水道：使用日数が15日以内なら定額部分を280円、16日以上なら560円とする。従量部分は実際の使用水量で計算する（換算しない）
- その月の日数は暦日数
- 検算：20mm・31日の月に18日使用・15m³なら、水道2,154円、下水道1,463円

```js

                 address: "東京都〇〇区サンプル町1-2-3",       // 契約住所
                 note: "" } ],
  contracts: [ { id: "C001", buildingId: "V001", customerNo: "0000000001",
                 holder: "サンプルハイツ管理組合",             // 契約者名
                 label: "1-5F分",                              // 契約名（表示名）
                 prevStart: "2026-06-20", prevEnd: "2026-08-20",
                 caliber: 20, note: "" } ]   // 同じbuildingIdの契約は配列の順に契約1〜5として表示

                    confirm: { state: "match", basis: "<確認時の計算条件>" },
                    confirmParts: null } }, ... } }

  // confirm（確認状態）は回答の金額とは別に保存する（6.1節「確認状態」）
  // confirmParts（W）：null＝内訳は未確認／{ basis }＝内訳（水道・下水道）も一致を確認した（confirm が match のときだけ。6.1.5）
  //   null                                   未確認
  //   { state: "match",    basis }           ［一致］を押した
  //   { state: "mismatch", basis }           ［違う］を押した
  //   { state: "stale", from, basis }        確認後に計算条件が変わった（再確認が必要。from は元の状態）

{ buildingId: "V001", startedAt: "2026-10-31T05:00:00.000Z",
  phoneStartedAt: null,   // 電話中なら開始時刻

// localStorage キー: wbc.timelogs
[ { id, mode: "tool" | "manual", buildingId, contractCount, startedAt, endedAt,
    seconds, phoneSeconds: null, note: "" } ]
  // contractCount：物件の契約数（表示している最大5件）。手作業の記録でも物件を選ぶと同じ値を入れる
  // 手作業の記録：startedAt は日付（YYYY-MM-DD）、endedAt は null、seconds は分×60
```
- マスタの日付はISO形式の文字列（`YYYY-MM-DD`）で持つ。照会入力の日付は入力欄の文字列（`YYYY/MM/DD` に整えたもの）で持ち、計算に渡す前に `YYYY-MM-DD` に変換する
- 契約の `id` は一意な文字列で、画面には表示しない。マスタで契約を追加するときに自動で採番し、編集しても変えない
- 照会の入力は契約IDに紐付ける。契約の削除や並べ替えをしても、入力値が別の契約に移らないようにする（削除された契約の入力は表示しない）
- 6件目以降の契約は表示せず、「6件目以降は表示されません」と警告する
- **保存済みデータの移行**（読み込み時に自動で行う。契約IDは変えない）
  - マスタ（版番号なし＝版1 → 版2）：物件に `name`（空文字）を追加する。契約の `location` を `label` に移す
  - 照会入力：欠けた項目を補い、日付を `YYYY/MM/DD` に整える。確認状態が無い行は**未確認**とする。旧データに回答金額が残っていても、確認したとは推定しない（金額は保持する）。利用者が新しい画面で確認操作をして初めて確認状態を記録する
  - 形の正しくない確認状態は捨てて未確認にする

## 6. 画面仕様

1ページ構成で、タブで切り替える：**料金確認**（メイン）／**物件マスタ**／**作業時間**／**料金表・設定**。

### 6.1 料金確認タブ

#### 画面の配置（上から順に）
1. **ヘッダー**：ツール名、作業時間タイマー（経過時間の表示と開始・停止の状態）
2. **物件情報**：物件番号のセレクト（「V001 サンプルハイツ」のように物件番号＋物件名。住所は出さない）、物件名、契約住所、契約件数
   - 契約者名は、物件内の全契約で同じなら物件情報に1回だけ表示し、異なる場合は契約ごとに表示する（4.の表）
3. **使い方の枠（連絡先を含む）**：物件情報の右側に置く（画面幅が狭いときは下に回り込んでよい）。薄いグレーなど控えめな色にし、赤は使わない（赤は入力エラー・差異などの警告専用）。物件のお客様番号や住所などの値は表示しない。印刷しない。「連絡先」の欄は別に設けない。枠の中の並びは次のとおり
   1. 説明文：「『水道使用量のお知らせ』が届いていない場合、最新の期間の使用量・合計金額を電話で問い合わせます。」
   2. 水道局 お客さまセンターの電話番号と受付時間
   3. 「電話で聞かれる項目：お客様番号／住所／契約者名／自分の電話番号」
   4. 自分の電話番号
   - 電話番号は `tel:` リンクにする
4. **契約情報と照会結果の入力**（1つの表に統合する。電話1回で物件内の全契約を1件ずつ照会する流れに合わせる）
   - 列見出し：1行目に契約名（表示名。空欄なら「契約1」など）、2行目にお客様番号。お客様番号の前に小さめのグレーで「お客様番号」のラベルを付ける。番号は電話の最初に読み上げるので、契約名と同じくらいの大きさの太字にし、数字の幅をそろえる（tabular-nums）。コピーボタンは置かない（マウスで選択してコピーできればよい。ラベルは選択の対象にしない）
   - 契約ごとの列に、上から：契約者名（契約ごとに異なる場合だけ）、前回期間（`2026/06/20〜2026/08/20`）、口径、今回期間の開始日・終了日、日数（自動）、使用水量、基本料金無償化（設定でオンのときだけ）、計算額（水道・下水道・**合計を大きく**、税込）、確認（［一致］［違う］と状態）
   - 表の上に、問い合わせ日（物件で1つ）、入力欄の色の凡例、基本料金無償化の説明（「？」。設定でオンのときだけ）を置く。表の下に対応者メモ（物件で1つ）を置く
   - 入力の詳細は 6.1.1〜6.1.5
5. **計算結果と照合**（6.1.6）
6. **内訳（税抜・月別）**：折りたたみ表示。月別の水量・基本料金・従量料金。画面で開いているときだけ印刷する（7.4節）
7. **PDF保存**：照合結果（5.の表と注記）のすぐ下に、目立つ色の［PDF保存（印刷）］ボタンを置き、そのすぐ横に次を縦に並べて表示する。注意はどちらも橙で表示し（赤は使わない）、印刷は止めない
   - 保存されるファイル名（7.3節）。生成できないときは「ファイル名を生成できません：理由（印刷はできます）」
   - 確認が済んでいない契約があるとき：「確認が済んでいない契約があります：受水槽（再確認が必要）、散水栓（未確認）（印刷はできます）」。対象は状態が「再確認が必要」「未確認」「入力エラー」「期間エラー」の契約（契約の順。名前は契約名（表示名））
8. **入力をクリア**：ページの最下部の右端に、小さく控えめなボタンで置く。［PDF保存］から離し、押し間違いで入力が消えないようにする

#### 6.1.1 入力欄の共通事項
- **入力欄の色**（役割ごと。凡例を文章で表示する）：必須（開始日・終了日・使用水量）＝薄い黄色、回答（［違う］で開く入力欄）＝薄い水色、任意（問い合わせ日・基本料金無償化（設定でオンのとき）・対応者メモ）＝白。入力エラー・期間エラーの赤枠と赤い警告は、どの色よりも優先して目立たせる
- **Tab順**：契約ごとに縦に進む。開始日 → 終了日 → 使用水量 → 基本料金無償化 → ［一致］ → ［違う］ → 内訳も一致を確認した（チェック欄） →（開いていれば）水道局の合計 → 内訳の開閉 →（開いていれば）水道 → 下水道 → 次の契約の開始日。無効な要素・閉じた入力欄は飛ばす。最後の契約の最後から Tab で表の外（直後の要素）へ、最初の開始日から Shift＋Tab で表の前へ抜ける。ボタンは Enter・スペースで押せる
- 日数は `終了日 − 開始日`（例：2026/08/20〜2026/10/20 は61日）。両方が入っていなければ空欄

#### 6.1.2 日付の入力（開始日・終了日・問い合わせ日。文字入力）
- 受け付ける形式：`2026/08/20`、`2026-08-20`、`2026.08.20`、`2026/8/20`、`20260820`（全角数字も可）。コピー＆ペーストで入力できる。ブラウザの入力候補は出さない（`autocomplete="off"`）
- 入力欄の見本（プレースホルダー）は、入力済みの日付と見間違えない形にする：「例：20260820」
- 入力欄を離れたら `2026/08/20` の形式に整えて表示する。存在しない日付や読めない形式は、入力欄を赤枠にして理由を表示する
- 変換は `js/parse.js` の純粋関数で行い、計算関数には `YYYY-MM-DD` で渡す
- **契約1の期間の自動コピー**：契約1の開始日・終了日が両方正しい日付で、終了日が開始日より後になった時点（入力欄を離れたとき）で、契約2〜5のうち空欄の開始日・終了日に同じ値を入れる。入力途中の値はコピーしない。入力済みの値は上書きしない

#### 6.1.3 数値の入力（使用水量・回答額）
- 空欄なら null、それ以外は整数に変換する。全角数字・全角カンマ・3桁区切りのカンマ（例：「9,038」「９，０３８」）を受け付ける
- 数値として読めない値・負の数・小数は計算に渡さず、入力欄を赤枠にして理由を表示する。その契約の判定欄は「入力エラー」と表示し、計算結果は空欄にする
- 入力中の値（例：「9,0」）ではエラーを出さず、入力欄を離れたときに判定する
- 入力エラーの契約は、建物合計の判定では「未入力」として扱い、金額の合計には含めない。表の上に「契約○：入力エラーがあります」と表示し、建物合計だけを見ても見落とさないようにする

#### 6.1.4 基本料金無償化
- **表示の設定**：「料金表・設定」タブの「基本料金無償化の入力欄を表示する」（`settings.showBasicFree`、初期値オフ）
  - オフのときは、無償化の行（チェック欄）、「？ 基本料金無償化とは」の説明、「無償化の対象期間ではありませんか？」の案内、凡例の「基本料金無償化」の記述を、画面にも印刷にも出さない。無償化なしとして計算する
  - オフにしたとき（初期値のオフで読み込んだときを含む）は、照会入力に残っている無償化のチェックをすべて外す（チェックの状態は残さない）。これで計算額が変わった確認済みの契約は「再確認が必要」になる（6.1.5の仕組み）
  - 計算ロジック（`calcBimonthly` の `basicFree`）、cases.json の無償化のケース、案内の判定（純粋関数）とそのテストは残す
- 以下は、設定がオンのときの扱い
- 欄の名前は「基本料金無償化（都の期間限定措置）」。「水道局から『基本料金は無償』と言われた場合だけチェック」と添える
- 「？」で次の説明を表示する：「東京都が2026年夏に実施した期間限定の措置です。口径13・20・25mmの契約は、水道の基本料金が4か月分無償になりました（6月1日検針分から。検針月により5〜6月分と7〜8月分、または6〜7月分と8〜9月分）。申請は不要です。水道局から「基本料金は無償」と言われた場合だけチェックしてください。」出典：東京都水道局 報道発表（2026年5月15日）
- 口径30mm以上の契約ではチェック欄を無効にし、「対象外」と表示する
- **案内**：次の条件をすべて満たすとき、その契約の確認欄と結果の表の上に「基本料金無償化の対象期間ではありませんか？」と表示する。確認を促すだけで、無償化を自動で適用しない。判定は変えない
  - 無償化のチェックがOFF／口径が25mm以下／確認状態が［違う］（再確認が必要ではない）／水道局の合計が入力済み（合計、または水道＋下水道）／入力エラー・期間エラーがない／水道局の合計が、無償化した場合の計算額（合計）と一致する

#### 6.1.5 合計の確認
水道局は通常、期間・使用水量・合計金額を答える。内訳は聞かないと答えないため、内訳は計算し、合計の一致を確認する。
- 使用水量などがそろうと、契約ごとに計算額（水道・下水道・合計、税込）を表示する
- 確認ボタンは合計に対して［一致］［違う］の2つ。開始日・終了日・使用水量がそろっていない、入力エラーがある、期間エラーがある間は押せない
  - ［一致］：計算した合計を水道局の回答（合計）として記録する。［違う］の中で入力していた内訳の回答は消す
  - ［違う］：水道局の合計の入力欄を開いてフォーカスする。金額を入力すると差額と判定を表示する。補助として「内訳（水道・下水道）も聞いた場合」の入力欄を折りたたみで置く（通常は使わない）
- **確認状態**（回答の金額とは別に保存する。判定は `judgeContract` をそのまま使い、渡す回答の値だけを状態に応じて組み立てる）

  | 今の状態 | 操作 | 次の状態 | 記録する値 |
  |---|---|---|---|
  | 未確認 | ［一致］ | 一致 | 回答（合計）＝計算額、内訳の回答は空。計算条件を記録 |
  | 未確認 | ［違う］ | 違う（金額を入力するまでは「未確認」と表示） | 計算条件を記録 |
  | 違う | 金額を入力 | 違う（判定結果：差異あり、または同じ額なら一致） | 入力した金額 |
  | 違う | ［一致］ | 一致 | 入力した金額を計算額に置き換える |
  | 一致 | ［違う］ | 違う（金額は未入力） | 記録した合計を消す |
  | 一致・違う | 計算条件が変わる | 再確認が必要 | 一致から：記録した計算額を消す。違うから：入力した金額は残す |
  | 再確認が必要 | ［一致］／［違う］（違うからの再確認では金額の入れ直しでも可） | 一致／違う | 計算条件を記録し直す |
  | すべて | 入力をクリア | 未確認 | すべて消す |

- **内訳の確認（W）**：［一致］のあとに、チェック欄「内訳（水道・下水道）も一致を確認した」を選べる（ホームページや電話で確かめた場合だけ）。合計の確認（`confirm`）とは別に `confirmParts: null | { basis }` として保存する
  - チェックできるのは状態が「一致」のときだけ（それ以外ではチェック欄を灰色にして押せなくする）。チェックすると状態の表示は「一致（内訳も確認）」。折り返すときは「一致／（内訳も確認）」のようにカッコの前で改行する
  - 説明「内訳のチェックは、ホームページや電話で確かめた場合だけ」は、左の項目欄「確認（合計）」の下に1回だけ、小さなグレーの文字で表示する（印刷しない）
  - チェックを外すと、合計の確認だけが残る。［違う］を押すと消える。［違う］・再確認が必要から［一致］に戻したときは、内訳は未確認（改めてチェックが必要）。同じ条件のまま［一致］を押し直した場合は残す
  - 計算条件が変わると、合計の確認と一緒に失効する（再確認が必要）。入力をクリアすると消える
  - 保存データに `confirmParts` がない、形が正しくない、合計の確認が「一致」でない、計算条件が合計の確認と違う場合は null（確認したと推定しない）
  - ［違う］のときの「内訳（水道・下水道）も聞いた場合」の入力欄は今のまま残す（聞き取った金額を記録する欄。チェック欄とは役割を分ける）
- **内訳の合計の警告（AF）**：［違う］で合計・水道・下水道の3つとも正しく入力し、水道＋下水道が合計と合わないときは、入力欄の下に赤い警告「水道＋下水道（21,752円）が合計（21,754円）と合いません。聞き直してください」を表示する。入力の途中でもすぐに表示し、印刷にも出す。片方だけ入力したとき・入力エラーがあるときは出さない。表示だけの扱いで、`judgeContract` と判定の結果は変えない
  - Tab順：［違う］の次にチェック欄（押せないときは飛ばす）。スペースキーで切り替える。入力欄の色は「任意」（白）で、凡例の任意の項目に「内訳の確認」を加える

- **再確認が必要になる条件**：確認したあとに、計算条件（期間・使用水量・無償化・口径・消費税率）が確認時と変わったとき。比べるのは変換後の値なので、日付の書き方を整えただけでは変わらない。値を元に戻しても確認済みには戻らない
- 判定関数に渡す回答：未確認・再確認が必要＝すべて null（判定は「未入力」）／一致＝合計だけ／一致＋内訳も確認＝合計と、水道・下水道の計算額（判定は一致、差額は0）／違う＝入力した合計と、入力していれば内訳
- 状態の表示：未確認＝黄、一致＝緑、差異あり＝赤、再確認が必要＝橙

#### 6.1.6 計算結果と照合
契約ごとの列と建物合計の列（契約を横に並べる。列見出しは4.の表と同じく契約名と、ラベル付きのお客様番号）。
- **列の位置をそろえる**：4.の表（契約情報と照会結果の入力）・この表・内訳の表は、どれも「項目の列＋契約1〜5の列＋右端の列」の7列にする。右端の列は、この表では「建物合計」、ほかの表では罫線も文字もない空の列とし、建物合計と同じ幅にする。項目の列と契約の列の幅も、3つの表で同じ値にする（画面：項目210px・契約と右端150px、印刷：項目46mm・残りを等分）。印刷で契約が無い列を出さないときは、3つの表で同じ列が消えるので、位置はそろったままになる
- 行：水道（基本・従量・消費税・計算結果・回答・差額・判定）、下水道（同じ項目）、合計（計算結果・回答・差額）、照合方法、総合判定
- 見出しに使用中の消費税率を表示する（例：「消費税率 10%」）
- 差額は `回答 − 計算結果`
- **照合方法**：「合計で照合」（合計だけを確認）／「内訳も照合」（［違う］で内訳も入力、または［一致］で内訳も一致を確認）／「未確認」／「再確認が必要」。PDFにも出す
- **内訳も一致を確認した契約**（W）：水道・下水道の判定は「一致」、差額は0。「水道局の回答」の水道・下水道の欄には、水道局から金額を聞き取って記録したように見えないよう、計算額の数字ではなく「計算額どおり」と表示する（画面・印刷とも。表示だけの扱い）。建物合計の列は、水道・下水道の回答のある契約がすべて内訳も確認した契約なら「計算額どおり」、聞き取った金額のある契約が混ざれば合計の金額を表示する
- 合計で照合した契約では、聞いていない内訳の「水道局の回答」を「—」とし、水道・下水道の判定欄には、画面でも印刷でも、小さなグレーの文字で「合計で照合」とだけ表示する（背景色は付けない。「—（合計で照合）」や「—」は使わない）。建物合計の列も同じ扱い。表示だけの扱いで、判定ロジックは変えない（内部の値は `TOTAL_ONLY`）
- 表の下に「水道・下水道の金額は、使用水量から計算した値です。照合方法が『合計で照合』の契約は、内訳（水道・下水道）を水道局に確認していません。」と表示する（PDFにも出す）
- 建物合計の列（Excel版と同じ）：金額は値のある契約だけを合計する（回答が1件も無ければ空欄）。差額は差額の出ている契約だけを合計する。判定は7.2節の優先順位で、水道・下水道・総合それぞれに付ける。水道・下水道の判定は「合計で照合」の契約を除いて決め、全契約が合計で照合なら「合計で照合」と表示する
- **建物合計で、内訳を確かめた契約が一部だけのとき**：内訳を確かめた契約（［違う］で内訳を入力、または［一致］＋内訳も確認）と、合計だけで照合した契約（判定欄が「合計で照合」）が混ざっているとき（水道・下水道それぞれで決める。`buildingPartScope`）は、建物全体を確かめたように読めないよう、建物合計の列を次のように表示する。表示だけの扱いで、`sumBuilding` と判定ロジックは変えない。表の下の注記は加えない
  - 水道局の回答・差額：小さなグレーの「一部のみ」
  - 判定：「一致」になる場合は小さなグレーの「一部のみ」。差異あり・期間エラー・未入力は、そのまま出す（確かめた契約の差異を目立たせるため）
  - 全契約で内訳を確かめたとき、どの契約も合計だけで照合したときは、これまでどおり
- 表の上の警告：入力エラー・期間エラー（赤）、再確認が必要・無償化の案内（橙）。期間エラーの契約も、使用水量があれば計算結果を表示する。判定欄を赤地の「期間エラー」にし、開始日・終了日の入力欄を赤枠にして、「契約○：終了日が開始日以前です（期間エラー）」と表示する
- 判定の色：一致＝緑、差異あり＝赤、期間エラー＝赤、未入力＝黄、合計で照合＝小さなグレーの文字（背景なし）

### 6.2 物件マスタタブ
- 物件一覧と契約一覧を表で表示し、追加・編集・削除できる
  - 物件の一覧：物件番号・物件名・契約住所・契約数・備考と、［契約を表示］［編集］［削除］
  - 契約の一覧：選んだ物件の契約を、料金確認の契約1〜の順に表示する（順・契約名（表示名）・お客様番号・契約者名・前回期間・口径・備考）。［上へ］［下へ］で並べ替え、［編集］［削除］
  - 追加・編集は一覧の下の編集欄で行い、［保存］／［キャンセル］。誤りは入力欄の赤枠と理由で示し、保存しない
- 項目名：物件は「物件番号・物件名・契約住所・備考」、契約は「物件番号・お客様番号・契約者名・契約名（表示名）・前回期間・口径・備考」
- 契約名（表示名）の入力欄に「例：1-5F分、共用栓」と添える
- **入力チェック**（`js/master.js` の純粋関数）
  - 物件番号：必須。半角の英数字とハイフン（20文字まで。全角で入力しても半角に直す）。重複不可（大文字・小文字は区別しない）。**追加するときだけ入力でき、あとからは変えられない**（ファイル名・照会入力・作業時間の記録が物件番号に結び付いているため）
  - 物件名：必須
  - お客様番号：必須。**半角数字10桁**（先頭の0も入力する）。入力欄に見本「例：0000000001」と、欄の下に「半角数字10桁（先頭の0も入力）」の説明を出す。全角数字は半角に直し、前後の空白は除く（ほかの番号類と同じ）。**数値には変換せず、先頭の0を保持した文字列として保存・比較する**。10桁の数字でなければ「お客様番号は半角数字10桁で入力してください」（数字だけのときは「（今は9桁）」のように桁数を添える）
  - お客様番号の重複：ほかの契約（別の物件も含む。編集中の契約自身は除く）と同じ番号は不可。理由に使っている場所を出す（例：「この番号は V001 サンプルハイツ『1-5F分』で使われています」。契約名が空欄なら「V001 サンプルハイツの契約」）
  - 前回期間：日付の文字入力（6.1.2と同じ形式）。両方空欄は可。片方だけ・存在しない日付・終了日が開始日以前は不可
  - 口径：料金表にある口径から選ぶ
- **エラーの出し直し**（物件・契約の編集欄）：欄を離れた時点で判定し直し、直って正しくなった欄のエラーを消す。まだ誤りがあれば理由を新しい内容に変える。表全体は描き直さず、エラーの表示だけを変える
  - 対象：今エラーが出ている欄と、この編集で触れた（離れた）欄。まだ触れていない欄には、［保存］を押すまでエラーを出さない
  - 前回期間の開始日・終了日は組で判定する。片方を直したときも両方を判定し直す（例：「終了日は開始日より後の日付にしてください」のあと開始日を直すと、終了日の欄のエラーも消える）。開始日だけ入れて離れたときに、まだ入力していない終了日へ「両方を入力」は出さない
  - 入力欄にカーソルがあるままボタンを押したときは、押した時点ではカーソルを動かさない（エラーの表示が変わってボタンの位置がずれ、押し損じるのを防ぐ）。［保存］ではすべての欄を判定する
- 契約IDは追加時に自動で採番し、画面には出さない。編集・並べ替えでは変えない。契約は物件の最後に追加する
- 6件目以降の契約は一覧で「料金確認に表示されません」と示し、「契約が○件あります。6件目以降は料金確認に表示されません。」と警告する（料金確認タブも同じ警告）
- **物件の削除**：その物件の契約も一緒に削除する（確認あり）。照会中の物件なら照会入力をクリアし、計測中ならタイマーを破棄する。作業時間の記録は残し、物件の欄に「（削除済み）」と表示する（作業時間タブ・CSV）
- **契約の削除**：確認のうえ削除し、その契約の照会入力も消す
- 「初期データ（架空）に戻す」ボタン（確認ダイアログを出す）：マスタと設定を初期データに戻し、照会入力をクリアし、タイマーを破棄する。作業時間の記録は残す
- 画面上部に「実在の個人情報は入力しないでください（公開デモ版）」と常に表示する

### 6.3 作業時間タブ（F8）
- 記録の一覧（新しい順）：日時、方式（ツール／手作業）、物件、契約数、所要時間、電話時間（任意）、メモ、削除。マスタから削除された物件は「（削除済み）」と表示する
- **手作業の記録の手入力欄**（mode = manual）：日付、物件、契約数（物件を選ぶと物件の契約数が自動で入る。編集しない）、所要時間（分。1以上の整数）、電話時間（分・任意）、メモ
- 集計：方式ごとの件数・平均時間（分）・1契約あたりの平均時間（分）。改善前後の差（1契約あたり）と削減率を表示する。両方の記録がそろうまでは「手作業とツールの両方の記録があると表示します」と出す
  - 1契約あたり＝所要時間の合計 ÷ 契約数の合計
  - 削減率＝（手作業の1契約あたり − ツールの1契約あたり）÷ 手作業の1契約あたり
- CSV出力（UTF-8 BOM付き・改行はCRLF。Excelで文字化けしないようにする）。ブラウザ内で作ってダウンロードする（外部通信なし）
  - ファイル名：`作業時間_YYYYMMDD.csv`
  - 列：方式、物件番号、物件名、契約数、開始日時、終了日時、所要時間（秒）、所要時間（分）、電話時間（秒）、メモ
  - カンマ・引用符・改行を含む値は `"` でくくる。`= + - @` で始まる文字列は先頭に `'` を付ける（Excelで数式として扱われないようにする）
- 記録の削除と、全件削除（確認あり）

### 6.4 料金表・設定タブ
- 料金表（4章の内容）を読み取り専用で表示する。表は `rates.js` の値から作る（数値を二重に書かない）：水道の基本料金（口径別）、水道の従量料金（1か月の水量の段階 × 口径区分）、下水道（8m³までの定額と段階ごとの単価）。口径30mm以上の単価は公式表の結合セルから読み取った値だと注記する
- 出典リンク（東京都水道局・東京都下水道局の料金表）：利用者がクリックしたときだけ新しいタブで開く普通のリンク（`target="_blank" rel="noopener noreferrer"`）。ページを開いただけでは通信しない
- 設定（入力欄を離れたとき、または Enter で保存する。誤りは赤枠と理由で示し、保存しない）
  - 消費税率：0〜99の整数（%）
  - 自分の電話番号：数字・ハイフンなど。料金確認の使い方の枠に表示する
  - 基本料金無償化の入力欄を表示する（チェック。初期値オフ。6.1.4）
  - 水道局 お客さまセンターの番号と受付時間は表示だけ（変更できない）
- 消費税率を変えると、全体の計算結果が即座に変わる（確認済みの契約は「再確認が必要」になる）

## 7. ロジック仕様（Excel版の最終仕様と同じにする）

### 7.1 契約ごとの判定
前提条件として、口径が未設定（契約が存在しない）列は空欄にする。
1. 開始日と終了日の両方があり、`終了日 <= 開始日` なら → **期間エラー**（水道判定・下水道判定・総合判定のすべて）
2. 使用水量・開始日・終了日のどれかが未入力なら → **未入力**（使用水量が未入力の間は計算結果も空欄にする）
3. 水道判定：回答（水道）が未入力なら未入力、差額が0なら一致、それ以外は差異あり
4. 下水道判定：水道判定と同じ考え方
5. 総合判定：
   - 水道判定または下水道判定が「差異あり」なら → **差異あり**（**合計の差額が相殺されて0でも差異あり**）
   - 合計の回答が取れない場合 → **未入力**。合計の回答は、回答（合計）があればそれを使い、なければ回答（水道）＋回答（下水道）。両方揃っていなければ取れないとみなす
   - 合計の差額が0なら → **一致**、それ以外は → **差異あり**
- 使用水量の0は有効な入力（基本料金だけになる）。空欄と区別する

### 7.2 建物合計の判定
契約の判定に、期間エラー → 差異あり → 未入力 → 一致 の優先順位で、最も重いものを採用する。

### 7.3 PDFファイル名
形式：`{物件番号}水道{開始日yyyymmdd}-{終了日mmdd}[（{n}件）].pdf`
- 開始日と終了日の両方が入った契約を対象にする
- 期間は、**開始日が最も早い契約**の開始日と終了日を使う（同じ開始日の契約が複数あれば、契約の順番で最初のもの）
- 対象が2件以上なら `（n件）` を付ける（全角かっこ）。nは期間を入力した契約の数
- 生成しない条件（理由を表示する）：
  - 物件が未選択
  - 期間がどの契約にも入っていない
  - 開始日・終了日の片方だけが入った契約がある
  - `終了日 <= 開始日` の契約がある
- 例：`V001水道20260820-1020（3件）.pdf`

### 7.4 PDF保存（F6）
- `window.print()` を使う。印刷の直前（`beforeprint`）に `document.title` をファイル名（`.pdf` を除いたもの）に変え、`afterprint` で元に戻す。ChromeやEdgeの「PDFに保存」で、これが初期ファイル名になる。Ctrl＋P で印刷した場合も同じ扱いにする（料金確認タブを表示していて物件を選んでいるとき）
- 印刷用CSS：A4縦。上から、見出し（タイトルの横に作成日時と保存されるファイル名）、物件情報、契約情報と照会結果（確認状態を含む）・問い合わせ日・対応者メモ、計算結果・照合（照合方法と注記を含む）、内訳（開いているときだけ）。タブ・ボタン・タイマー・使い方の枠（連絡先を含む）・凡例・案内文・「？」の説明・入力欄の見本は印刷しない
- **入力欄の値の印刷**：料金確認の入力欄（開始日・終了日・使用水量・回答額・問い合わせ日・対応者メモ）は印刷しない。印刷の直前（`beforeprint`）に、各入力欄の値を同じセルの中の印刷用の文字に写し、その文字を印刷する。文字はセルの幅で折り返し、数値は右寄せにする（入力欄のままだと、欄の幅がセルより広いときに右寄せの数字が隣の列にはみ出し、別の契約の値に見えるため）
- **改ページ**：強制的な改ページはしない。表の途中ではページを切らず、収まらなければ表ごと次のページへ送る。「計算結果と照合」の見出し・警告・表・注記は必ず同じページに置く（見出しだけが前のページに残らないようにする）
- **ページ数**：1〜3契約の物件は倍率100%で1ページ、5契約の物件は2ページ以内を目指す。読みやすさを優先し、まず行の高さ・セルの余白・見出しの間隔を詰める。物件情報は項目を横に並べ、契約が無い列（契約4・5など）は印刷しない。それでも収まらない場合に限り、表の文字を8.5ptまで小さくしてよい（それより小さくしない）
- **途中で改行しない文字**（Y・Z）：計算額（「水道 1,232円」など）は金額と「円」を分けない。折り返すときは「水道」「下水道」「合計」と金額の間で改行する。前回期間は、折り返すときは「〜」のあとで改行し、日付の途中では切らない。2行になるときは、1行目の「開始日〜」を左寄せ、2行目の終了日を右寄せにする（AD。画面も同じ。1行に収まるときは詰めて左寄せのまま）
- **回答額の印刷**（AE）：確認（合計）の欄の水道局の回答（合計・水道・下水道）は、「21,754円」の形に整えて印刷する（正しく読めない値は入力のまま）
- **内訳の確認**（W）：チェック欄そのものは印刷しない。チェックした契約は、確認のセルの状態に「一致（内訳も確認）」と印刷する。内訳も確認した契約が1件でもあれば、計算結果の表の水道・下水道の「水道局の回答」（「計算額どおり」）・「差額」（0）の行を印刷する
- 作成日時とファイル名は最初のページの見出しの横に置く（最後のページにそれだけがあふれないように）
- 行の見出しの列は、「下水道　差額（回答－計算）」などの見出しが折り返さない幅にする
- **内訳を聞いた契約が1件もないとき**（水道・下水道の回答がどの契約にも無いとき）は、計算結果の表の水道・下水道の「水道局の回答」「差額（回答－計算）」の行を印刷しない（画面には今のまま表示する）。判定の行は印刷する
- **内訳（税抜・月別）**は、画面で開いているときだけ印刷する。印刷の直前に自動で開くことはしない。閉じているときは見出しの行も含めて印刷しない
- ファイル名を生成できない状態でも印刷はできる。ただし［PDF保存］ボタンの横に「ファイル名を生成できません：理由」と警告を出す

### 7.5 クリアと物件切替（F7）
- 「入力をクリア」：照会結果の入力欄（問い合わせ日・各契約の入力・メモ）だけを消す。マスタと設定は消さない。確認ダイアログを出す
- 物件番号を切り替えるとき、入力値が残っていれば「入力値が残っています。クリアして切り替えますか？」と確認する（Excel版の運用上の弱点を仕組みで解消する）

### 7.6 作業時間の計測（F8）
- 表示：ヘッダーに「作業時間 03:25」、計測中の物件、電話時間、［開始］［終了］［電話中／通話終了］ボタン。毎秒更新する。印刷しない
- **開始**：物件を選択したとき（またはタイマーの「開始」ボタン）
- **終了**：PDF保存（印刷）を実行し、印刷ダイアログを閉じた後に、ページの中の確認パネル（`<dialog>`）で「PDFを保存しましたか？」と確認する。［保存した（作業時間を記録）］を選んだ場合だけ終了する。［記録しない（計測を続ける）］を選んだ場合は計測を続ける（印刷をキャンセルしても `afterprint` が発生するため）。計測していなければ確認しない
- 手動の「終了」ボタンでも終了できる（その時点までを記録する）
- 終了時に記録を `wbc.timelogs` に追加し、「所要時間 ○分○秒 を記録しました」と表示する。契約数は物件の契約数（表示している最大5件。実務では1回の電話で物件内の全契約を照会するため）
- 計測中に物件の切替を確定した場合、それまでの計測は記録せずに破棄し、新しい物件で計測を始める。物件の選択を外した場合は破棄して止める
- 任意で「電話中」ボタンを押すと通話時間を別に計測し、`phoneSeconds` に記録する（待ち時間と作業時間を分けて分析するため）。電話中のまま終了した場合は、その時点までを加える
- タイマーの状態はリロードしても失われないようにする（開始時刻を `wbc.timer` に保存し、経過時間は開始時刻から計算する）。保存された状態が無ければ、物件が選ばれていても自動では始めない（物件の選び直しか［開始］ボタンで始める）
- 計算は `js/timer.js` の純粋関数で行い、現在時刻は引数で受け取る（テストで時刻を固定するため）
